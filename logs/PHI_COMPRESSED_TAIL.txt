========================================================================================
Compressed x + 02/03 tail  vs  Phi (x/p + y/p^2)
========================================================================================

  Compressed = prefix(y parity) || x
  User idea: decimal body from x; differing tail = 02 or 03

----------------------------------------------------------------------------------------
1) Negation: same x, flip 02 <-> 03
----------------------------------------------------------------------------------------
  walk 1..64: x unchanged under neg:     64/64
  walk 1..64: prefix flips, x hex same:  64/64
  walk 1..64: recover_y from (x,tail)= -P: 64/64
  Matches Phi: X=x/p invariant; only Fine/parity changes.

----------------------------------------------------------------------------------------
2) GLV psi: new x = beta*x, SAME parity (y unchanged)
----------------------------------------------------------------------------------------
  walk 1..64: prefix unchanged under psi: 64/64
  walk 1..64: x changes under psi:        64/64
  Matches Phi: Fine invariant under GLV; coarse X moves.

----------------------------------------------------------------------------------------
3) Information: compressed vs full Phi
----------------------------------------------------------------------------------------
  KEEP:  x (32 bytes) + 1-bit parity  => unique affine point via curve
  DROP:  full y magnitude in Phi Fine = y/p^2
  Tail 02/03 is NOT a decimal fraction of y — only parity.
  So 'differing tail' works for +/- orbit; it does not encode Fine digits.

5) Does compressed-x + tail make F cheaper?
----------------------------------------------------------------------------------------
  No. To add you still decompress (recover y) or stay in EC.
  Tail flip = negation only. x-body + tail has no schoolbook add rule.
  Same junction as Phi: orbit symmetries cheap; F is still EC.

========================================================================================
VERDICT
========================================================================================
  Yes: compressed x + 02/03 tail is the clean 'coarse + tag' form.
  Negation = identical x digits, flip tail. GLV = new x, same tail.
  That matches Phi layer symmetries without storing y/p^2.
  Cost: lose Fine decimal; recover y from curve when needed.
  Does not replace F; only clarifies the +/- half of the orbit.
